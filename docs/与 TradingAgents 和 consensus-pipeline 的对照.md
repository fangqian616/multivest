# 与 TradingAgents 和 consensus-pipeline 的对照

> 本文说明「家和智投」的设计选择从哪里来、为什么这样取舍。
> 两个参照项目：用户自己的 [consensus-pipeline](https://github.com/fangqian616/consensus-pipeline)
> 与 [TradingAgents](https://github.com/TauricResearch/TradingAgents)。

---

## 一、两个项目的强项与短板

| 维度 | consensus-pipeline | TradingAgents |
|---|---|---|
| **本质** | 部门辩论 + 立场量化 + 共识收敛 | 角色编排 + 固定流程 + 交易决策 |
| **辩论机制** | ✅ 更强：CV 量化、Kendall's W 交叉验证、动态终止、跨部门交叉辩论、QC 硬门禁。**收敛是被测量的** | ❌ `max_debate_rounds` 写死，跑完即停，从不检验共识是否形成 |
| **工程成熟度** | 较弱：一人深度定制的科研管线 | ✅ 更强：LangGraph、checkpoint 续跑、决策日志与跨标的经验注入、CI、Docker、多 provider、多市场 |
| **胜负裁判** | ❌ 无 ground truth，只能靠内部 QC 自证 | ✅ 有：回测收益（相对区域基准的已实现 alpha） |
| **决策粒度** | 共识综述 | 单标的买/卖/持 + 时机 + 规模 |
| **组合感知** | 无 | ✅ `PortfolioContext`（cash / currency / positions） |

**原判断（2026-09-09）**：论"辩论/共识机制的设计智慧"→ consensus-pipeline 更强；
论"能不能当产品被人拿去用" → TradingAgents 赢。
关键差异在于 TradingAgents 有明确胜负裁判，闭环验证真实；consensus-pipeline 没有标准答案。

## 二、本系统的取舍

### 取舍 1：机制取 consensus-pipeline，工程取向 TradingAgents 学

| 从 consensus-pipeline 移植 | 从 TradingAgents 借鉴 |
|---|---|
| CV 变异系数与 ε1/ε2 阈值 | 决策日志（`backend/runs/<id>/result.json` + `stance_log.jsonl`） |
| Kendall's W 联合收敛 | 项目上下文接地（家庭画像是 agent 运行前**确定性解析**的） |
| 三轨道动态终止（收敛/平台/僵持） | 结构化的分析师 → 辩论 → 风控 → 经理流水线 |
| 解析失败率门 | 独立表态采集（短输出，避免截断） |
| 复合僵局检测 | 多 provider / OpenAI 兼容后端 |
| QC 硬门禁 | 显式的"研究用途、非投资建议"定位 |
| 议题抽取 + 后验过滤 | — |

**没有照搬的**：LangGraph（本项目是单进程 Python，用 `ThreadPoolExecutor` + 事件
回调就够了，引入图编排框架会让部署和打包复杂化）、checkpoint 续跑
（家庭配置不需要逐标的恢复，一次审议是分钟级的原子任务）。

### 取舍 2：换赛道 —— 从"单标的择时"到"家庭大类配置"

TradingAgents 回答"买不买 NVDA"。这个赛道**有明确胜负裁判，但也最拥挤**，
且它的裁判（回测收益）在短窗口上噪声极大。

家庭资产配置是另一个问题域：

| 特征 | 单标的择时 | 家庭大类配置 |
|---|---|---|
| 决策对象 | 一个 ticker | 8 个大类 × 一个家庭的全部财务约束 |
| 目标 | 最大化风险调整收益 | **多目标**：教育金确定性、养老、流动性、还贷、保障 |
| 约束 | 资金量 | 应急金、杠杆、收入稳定性、承受力、期限匹配 |
| 正解 | 事后可判定 | **不存在唯一正解**，只有"是否满足这个家庭的约束" |
| 适合辩论吗 | 中等（容易变成同质化多空） | ✅ **高度适合**（角色天然互补，约束可校验） |

**关键洞察**：家庭配置没有 ground truth，但它**有硬约束**。
consensus-pipeline 的困境是"没有标准答案，只能靠内部 QC 自证"；
家庭配置恰好提供了另一种验证路径——**约束满足度可判定**：
权益是否超上限、应急金是否够、单一类别是否过集中、权重是否归一。
这把"无 ground truth"的软肋变成了"有可判定约束"的硬门禁。

这正是本系统 10 项 QC 门禁存在的理由。

### 取舍 3：分歧的处理 —— 显式裁决而非掩盖

多数多智能体系统（包括 TradingAgents）在辩论结束后由"研究经理"或"组合经理"
总结陈词。问题是：**如果辩论没有收敛，总结陈词会掩盖这一点。**

本系统的做法：
1. 每条主张的收敛状态被量化并**保留**（`disagreement_map`）
2. 未收敛（`deadlocked` / `partial`）的主张被列出
3. 配置委员会**必须逐条裁决**，写明采纳哪一方、依据、为什么另一方的顾虑不构成否决理由
4. **QC-9 强制校验**：裁决覆盖不全 → 硬门禁失败 → 方案不得交付

分歧从"需要被总结掉的麻烦"变成"必须被交代的产出"。

### 取舍 4：LLM 只出权重

TradingAgents 让 LLM 输出完整的交易决策（含理由）。本系统把 LLM 的输出面**收窄到 8 个数字**：

```
LLM 负责：判断（该超配什么、为什么、边界在哪）
系统负责：算术（多少钱、历史表现如何、最坏会亏多少、是否违反约束）
```

收益：
- **可复现**：同样的权重永远得到同样的历史回放与压力测试
- **可校验**：算术错误会被 QC 直接抓到，而不是淹没在散文里
- **可兜底**：权重空间只有 8 维且带约束，可以确定性生成一个安全解

代价：LLM 的定性判断（比如"这个家庭不该碰商品"）只能通过把 `commodity` 权重设成 0
来表达，无法直接写在权重里。这部分由 `class_rationale` 字段承载。

## 三、机制对照表（细节）

| 环节 | consensus-pipeline | TradingAgents | 家和智投 |
|---|---|---|---|
| 参与者 | 部门（文献/方法/反证） | 分析师（基本面/情绪/新闻/技术）+ 多空研究员 | 分析师（宏观/定价/期限/税费/行为） |
| 论点来源 | R1 后 LLM 抽取学术主张 | 无显式论点清单 | R1 后 LLM 抽取**配置主张**，并后验过滤掉宏观预测与数据描述 |
| 表态方式 | Likert 1-5，单独一问 | 无 | Likert 1-5，单独一问 |
| 收敛判定 | CV + W + 三轨道 | 无（轮数写死） | **同上**（阈值原样保留） |
| 领域适配 | 学术主张的判据 | — | 主张必须能落到**配置动作或比例**上 |
| 新增守卫 | — | — | **非中立守卫**（拦截集体打 3 分的假收敛） |
| 对抗性审查 | 跨部门交叉辩论 | 风控团队（波动/流动性） | 风控委员会（逐情景金额化 + 集中度/流动性/杠杆 + 否决权） |
| 最终裁决 | 共识收敛 | Portfolio Manager 批准/拒绝 | 配置委员会（含**未收敛主张的逐条裁决**） |
| 输出校验 | QC 硬门禁 | 无显式门禁 | **10 项硬门禁 + 兜底方案** |
| 记忆 | 经验沉淀 | 决策日志 + 跨标的经验注入 PM 提示 | 运行记录落盘（`runs/<id>/`），含完整 stance 日志 |

## 四、可以继续做的方向

1. **接入 TradingAgents 做对照实验**
   把同一个家庭画像分别喂给两套系统，比较：决策质量的稳定性、约束违反率、
   对同一输入的方差。TradingAgents 支持 `DEEPSEEK_API_KEY`，可以直接跑。

2. **把 QC 门禁回灌给 consensus-pipeline**
   本系统的 QC-9（分歧裁决覆盖率）是一个**与领域无关**的机制，
   可以直接移植回学术综述场景：未收敛的学术主张必须被显式交代。

3. **决策日志的经验注入**
   学 TradingAgents 的做法：把历史审议的"事后验证结果"（比如配的方案在半年后
   实际回撤是多少）注入下一次同一家庭的提示词，形成闭环。

4. **point-in-time 数据完整性**
   TradingAgents v0.5 的 SEC EDGAR 按申报时点读取，避免前视偏差。
   本系统目前用全样本统计历史参数，存在轻微的样本内偏差，
   可以做 walk-forward 的滚动参数估计。

5. **把"约束满足度"变成可发表的度量**
   本系统实际上提出了一个可测量的量：**在一组硬约束下，
   多智能体辩论收敛后的方案与随机方案相比，约束违反率降低多少**。
   这是一个有 ground truth 的评测框架——恰好补上 consensus-pipeline 最脆弱的地方。
